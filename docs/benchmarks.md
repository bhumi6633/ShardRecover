# Benchmarks

Measured on 2026-09-01 from a Release build; these are not universal performance claims.

## Environment

- macOS Darwin 24.0.0, arm64 (`T8122` platform identifier; CPU marketing name unavailable)
- 8 logical CPUs
- Apple Clang 16.0.0
- CMake Release build

## Graph construction

```sh
./build/shardrecover_graph_bench --fragments 100 --fragment-size 4096 \
  --overlap 512 --iterations 5 --strategy both --threads 1 --io both
```

| Strategy | I/O | Candidates | Full checks | Load ms | Graph ms | Total ms |
|---|---:|---:|---:|---:|---:|---:|
| exhaustive | buffered | 9,900 | 9,900 | 1.437 | 23.804 | 25.241 |
| indexed | buffered | 99 | 99 | 1.471 | 80.499 | 81.970 |
| exhaustive | mmap | 9,900 | 9,900 | 1.035 | 21.511 | 22.546 |
| indexed | mmap | 99 | 99 | 1.071 | 80.324 | 81.395 |

Indexing reduced full checks by 99%, but indexed buffered graph construction was 3.38× slower because index construction dominated this small workload. mmap reduced measured load time by about 28%, subject to warm-filesystem-cache effects.

## Thread scaling

```sh
./build/shardrecover_graph_bench --fragments 200 --fragment-size 4096 \
  --overlap 512 --iterations 5 --strategy exhaustive --threads N --io buffered
```

| Threads | Full checks | Graph ms | Total ms |
|---:|---:|---:|---:|
| 1 | 39,800 | 87.446 | 90.362 |
| 2 | 39,800 | 44.357 | 46.990 |
| 4 | 39,800 | 24.294 | 26.901 |
| 8 | 39,800 | 15.469 | 18.170 |

Eight threads produced a 5.65× graph-time speedup over one thread for this workload, not linear scaling.

## Recovery evaluation

All scenarios used 65,536 generated bytes, 1,024-byte fragments, 512-byte overlap, beam width 8, seeds 40–44, and five runs. Clean/clutter/drop used indexed construction; mismatch scenarios used exhaustive construction with one allowed mismatch and consensus repair.

| Scenario | Exact runs | Surviving recall | Mean selected noise | Relative order |
|---|---:|---:|---:|---:|
| clean | 5/5 | 100% | 0 | 100% |
| one corrupted byte | 3/5 | 100% | 0 | 100% |
| 3 duplicates + 3 noise | 5/5 | 100% | 3 | 100% |
| one dropped fragment | 0/5 | 78.254% | 0 | 100% |
| mixed damage | 0/5 | 78.254% | 0.8 | 100% |

The clean run’s mean pipeline time was 12.516 ms. Exact recovery is direct byte equality in the evaluation harness. Dropping a fragment can remove unique information; the engine does not claim to recreate it.

## Limitations

Generated benchmark data is deterministic and high entropy. Results include filesystem and allocation effects, depend on cache state and compiler, and do not establish performance on arbitrary forensic datasets. Algorithmic candidate reduction must be distinguished from wall-clock speed.
